### 1. Статистика волонтера

#### 👁️ Общедоступная (для самого волонтера и других волонтеров)
**Профиль:** 
*   Ник
*   Общее количество часов.
*   Общее количество мероприятий.
*   Часы/мероприятия за текущий сезон.
*   Список прошедших мероприятий (название, дата, часы).

**профиль для самого себя** 
* фио
* Контакты: имя, Телефон, Email, Telegram username, VK
* Дата рождения, Возраст, Пол.
* Полная история заявок 
* любимые мероприятия 

> Благодарственные письма в расширенном профиле не показываются — только в апп/на сайте, в карточке соответствующего мероприятия (для участников).


#### 🔒 Внутренняя (только для менеджеров)

*   **Статусы:** `active`, `blacklisted`.
*   **Комментарии:** Внутренние заметки менеджеров .
*   **Исключения:** Список требований, которым волонтер не соответствует (`user_requirement_exceptions`) + причины.
*   **Детальная аналитика:** Конверсия заявок, динамика активности.
*   **текущие отклики:** Находится ли сейчас с заявками на какие-либо меро и их статус 
*   чарн (`users.churn_score`, FLOAT) — коэффициент недобросовестности. Начисление `+churn_no_show_penalty` за неявку без предупреждения (`absent_unexcused`); списание за активность `−churn_activity_base / e^(меро за последний месяц + 1)`. При `churn_score ≥ churn_blacklist_threshold` — в блэклист до следующего сезона/учебного года. Все пороги — в таблице `const`. Точная формула и carryover по сезонам — бизнес-правило 9 в `db.md`.

# Спецификация отчётов и профилей

> Документ описывает все отчёты системы: какие данные выводятся, кому видны и откуда берутся.
> Уровни доступа: 👁 — все волонтёры · 👤 — только сам пользователь + менеджеры · 🔒 — только менеджеры · 👥 — участники данного мероприятия

---

## 1. Волонтёр

### 👁 Публичный профиль (видят все волонтёры)

| Поле | Откуда / как считается |
|------|------------------------|
| Никнейм (telegram_username) | `users.telegram_username` |
| Общее количество часов | `users.total_hours` — кэш, SUM(`participations.hours`) где `status = 'attended'` |
| Общее количество мероприятий | `users.total_event_count` — кэш, COUNT(`participations`) где `status = 'attended'` |
| Часы за текущий сезон | `users.season_hours` — то же, но с фильтром по `seasons.start_season … end_season` |
| Мероприятий за текущий сезон | `users.season_event_count` — аналогично с фильтром сезона |
| Список прошедших мероприятий | JOIN `participations` → `event_days` → `events`: название, дата (`event_days.day`), часы (`participations.hours`), только `status = 'attended'` |
| Статус «Звёздочка» ⭐ | производный признак: выдаётся автоматически, когда `users.season_hours ≥ const.pgas_hours_threshold` (закрытие ПГАС за сезон). Отдельной таблицы достижений нет |

---

### 👤 Расширенный профиль (только сам пользователь + менеджеры)

| Поле | Откуда / как считается |
|------|------------------------|
| ФИО | `users.first_name`, `users.last_name` |
| Телефон | `users.phone` |
| Email | `users.email` |
| Telegram username | `users.telegram_username` |
| VK | `users.VK_username` |
| Дата рождения / возраст | `users.birthday`; возраст — вычисляется на лету: `CURRENT_DATE - birthday` |
| Пол | `users.gender` (`male` / `female`) |
| Полная история заявок | `applications` WHERE `user_id = ?`: мероприятие, дата подачи, статус (`new` / `approved` / `rejected`) |
| Любимые категории | Топ-3 категорий из `event_category_map` JOIN `participations` — по частоте посещения |

> Благодарственные письма в расширенном профиле **не показываются**. Письмо доступно только в апп/на сайте — в расширенной (участник) карточке соответствующего мероприятия (см. §4 → 👥 Расширенная карточка). В боте писем нет.

---

### 🔒 Внутренний профиль (только менеджеры)

| Поле | Откуда / как считается |
|------|------------------------|
| Статус | `users.status`: `active` / `inactive` / `blacklisted` |
| Внутренний комментарий | `users.comment` — свободный текст, пишет менеджер |
| Дата регистрации | `users.created_at` |
| Дата последнего участия | `users.last_event_at` |
| Исключения из требований | `user_requirement_exceptions`: название требования (`event_requirements.title`), причина (`reason`), дата (`created_at`) |
| Текущие активные заявки | `applications` WHERE `user_id = ? AND status = 'new'` или `'approved'`: меро, дата подачи, статус |
| Конверсия заявок | approved / total по `applications` для данного `user_id`, в % |
| Churn score (текущий) | `users.churn_score` (FLOAT) — коэффициент недобросовестности на текущий момент (см. бизнес-правило 9 в `db.md`) |
| История churn по сезонам | `churn_history`: сезон (`season_id`), значение чарна на закрытие сезона (`churn_score`), дата |
| Динамика активности | Количество `participations` по месяцам — строится по `event_days.day` с группировкой по месяцу |

## 2. Тим-лидер

> Включает всё из профиля волонтёра (публичный, расширенный и внутренний), плюс следующие поля.

### 👁 Дополнительно в публичном профиле (видят все волонтёры и тим-лидеры)

| Поле | Откуда / как считается |
|------|------------------------|
| Количество мероприятий как тим-лидер (всего) | `team_leaders.total_events` — кэш, COUNT(`event_staff`) WHERE `staff_role = 'team_lead'` AND `user_id = ?` |
| Количество мероприятий как тим-лидер (сезон) | `team_leaders.season_events` — то же с фильтром текущего сезона |
| Дата назначения на роль тим-лидера | `team_leaders.assigned_at` (последняя активная запись, где `revoked_at IS NULL`) |

> У тим-лидера **нет** отдельного внутреннего профиля: все данные, которые отличают его от обычного волонтёра (кол-во меро как ТЛ, дата назначения), находятся в открытом доступе. В остальном действует внутренний профиль волонтёра.

## 3. Менеджер

### 👁 Публичный профиль (видят все волонтёры)

| Поле | Откуда / как считается |
|------|------------------------|
| ФИО | `users.first_name`, `users.last_name` (через `managers.user_id`) |

---

### 🔒 Внутренний профиль (только менеджеры)

| Поле | Откуда / как считается |
|------|------------------------|
| Контакты | `users.phone`, `email`, `telegram_username`, `VK_username` |
| Дата назначения | `managers.assigned_at` |
| Кто назначил | `managers.assigned_by` → ФИО |
| Обработано заявок (всего) | COUNT(`applications`) WHERE `assigned_by = ?` |
| Обработано заявок (сезон) | То же с фильтром `applications.created_at` в диапазоне текущего сезона |
| Среднее время обработки заявки | AVG(`applications.assigned_at - applications.created_at`) — только по заявкам, где `assigned_by = ?` |
| Текущие меро под управлением | `event_staff` WHERE `user_id = ? AND staff_role = 'manager'` JOIN `events` WHERE `event_status != 'finished'` |
| Меро под управлением (всего) | `managers.total_events` |
| Меро под управлением (сезон) | `managers.season_events` |

## 4. Мероприятие

### 👁 Публичная карточка (видят все волонтёры)

| Поле | Откуда / как считается |
|------|------------------------|
| Название | `events.title` |
| Описание | `events.description` |
| Даты проведения | `event_days.day` — список всех дней; MIN/MAX для диапазона |
| Время начала / конца | `event_days.start_time`, `event_days.end_time` |
| Локация | `locations.name` через `event_days.location_id` (может быть разной по дням) |
| Организация | `organizations.name` через `events.organization_id` |
| Категории / тематики | `event_categories.name` через `event_category_map` |
| Статус набора | `events.recruit_status`: `open` / `closed` — автоматически: `closed` когда COUNT(`applications` со `status='approved'`) ≥ `const.recruit_close_ratio` × SUM(`event_days.volunteer_needed`). Фактическая явка — отдельная метрика |
| Статус мероприятия | `events.event_status`: `upcoming` / `ongoing` / `finished` — по текущему времени vs `start_time` / `end_time` |
| Требования к волонтёрам | `event_requirements.title` через `event_requirement_map` |
| Тим-лидер | `users.first_name / last_name / telegram_username` через `event_staff` WHERE `staff_role = 'team_lead'` |
| Ссылка на пост в канале | `events.post_in_chanel_link` |
| Количество людей, которым помогли | `events.people_helped` — вводится тим-лидом или менеджером при закрытии смены (поле обязательное) |

---

### 👥 Расширенная карточка (только для участников данного мероприятия)

| Поле | Откуда / как считается |
|------|------------------------|
| Количество волонтёров на меро | COUNT(DISTINCT `participations.user_id`) WHERE `event_day_id` принадлежит данному меро |
| Ссылка на чат мероприятия | `events.chat_link` |
| Благодарственное письмо | если у меро задан `events.letter_id` — сгенерировать на лету из `thank_you_letter_templates` с подстановкой ФИО волонтёра (PDF не хранится) |
| Ссылка на Добро.ру | `events.dobro_ru_link` |
| Рейтинг мероприятия (средний) | AVG(`event_feedbacks.rating`) WHERE `event_id = ?` — показывается после завершения |
| CTA — оставить оценку | Если `event_feedbacks` WHERE `event_id = ? AND author_id = ?` не существует — показать форму оценки |

---

### 🔒 Внутренняя карточка (только менеджеры)

| Поле | Откуда / как считается |
|------|------------------------|
| Нужно волонтёров (итого) | SUM(`event_days.volunteer_needed`) по всем дням меро |
| Подтверждено участий | COUNT(`participations`) WHERE `event_day_id` IN (дни меро) AND `status = 'attended'` ИЛИ не проставлено ещё |
| Подано заявок | COUNT(`applications`) WHERE `event_id = ?` |
| Осталось набрать | SUM(needed) − COUNT(подтверждённых) |
| Контакты менеджера | `users.phone / telegram_username` через `event_staff` WHERE `staff_role = 'manager'` |
| Контакты тим-лидов | Аналогично WHERE `staff_role = 'team_lead'` |
| Контакты организатора | `organizers.phone / email / telegram_username / VK_username` через `events.organizer_id` |
| Список заявок | `applications`: ФИО, телефон, telegram, статус, дата подачи, функция, смена — с фильтрами |
| Проставлены ли часы на Добро.ру | `events.dobro_ru_hours_logged` (агрегат по attended-участникам), последний — `events.dobro_ru_logged_by` → ФИО |
| Тип учёта на Добро.ру | `events.dobro_ru_link_kind` (`none` / `shared` / `unique`) |
| Ссылка на Добро.ру | при `unique` — `events.dobro_ru_link`; при `shared` — `dobro_ru_shared_links.url` через `events.dobro_ru_shared_link_id` |
| Средний рейтинг (внутренний) | AVG(`event_feedbacks.rating`), количество отзывов |
| Внутренние комментарии | `events.internal_comment` — заметки по организации |
| Выбранный шаблон письма | `events.letter_id` → `thank_you_letter_templates.title` |

> Доступен только менеджерам.
>
> **Выбор охвата.** Отчёт строится по одному из **двух взаимоисключающих режимов**:
> - **По периоду:** пресет (неделя / месяц / сезон — сезон по датам `seasons`) или произвольный
>   диапазон дат через выпадающий календарь (дата начала — дата конца).
> - **По мероприятиям:** явный мультивыбор конкретных мероприятий из списка (по аналогии с
>   выбором диапазона). Границы дат при этом **игнорируются** — аналитика считается только по
>   выбранным меро. Блок «Сравнение с прошлым периодом» в этом режиме отключается.
>
> **Две вариации главного PDF.** Отчёт за период выпускается в двух отдельных документах:
> - **Внешний** — для руководства/ректората/грантодателей: только агрегированные показатели,
>   **без имён конкретных людей** и внутренней кухни (churn, blacklist, нагрузка персонала).
> - **Внутренний** — для менеджеров: всё из внешнего **плюс** персональные и операционные данные.
>
> Внешний отчёт — строгое подмножество внутреннего: всё, что входит во внешний, входит и во
> внутренний. Ниже блоки помечены: 🌐 — попадает в оба; 🔒 — только внутренний. Макеты обеих
> вариаций, Excel-листы, отчёт по мероприятию и простановка часов — в
> [reports_template.md](reports_template.md).

### Общие достижения сообщества

| Показатель | Доступ | Откуда / как считается |
|------------|--------|------------------------|
| Всего часов за период | 🌐 | SUM(`participations.hours`) WHERE `event_days.day` IN охват AND `status = 'attended'` |
| Всего мероприятий | 🌐 | COUNT(DISTINCT `events.id`) через `event_days` за охват |
| Уникальных волонтёров | 🌐 | COUNT(DISTINCT `participations.user_id`) за охват |
| Закрытых смен | 🌐 | COUNT(`participations`) WHERE `status = 'attended'` за охват |
| Новых волонтёров | 🌐 | COUNT(`users`) WHERE `created_at` IN охват |
| Людей, получивших помощь | 🌐 | SUM(`events.people_helped`) по меро за охват |
| Топ категорий | 🌐 | COUNT(`participations`) GROUP BY `event_categories.name` за охват |
| Топ волонтёров по часам | 🔒 | Никнейм + часы: SUM(`participations.hours`) GROUP BY `user_id` ORDER BY DESC, TOP-10 — **внутренний** (имена конкретных людей) |

> **График «Распределение по категориям» 🌐** — столбчатая диаграмма, высота столбца = число
> людей. Метрика столбца переключается: количество волонтёров / количество часов / количество
> мероприятий в категории. Обезличенная, попадает во внешний отчёт.

### Воронка набора 🌐

| Показатель | Откуда / как считается |
|------------|------------------------|
| Подано заявок | COUNT(`applications`) WHERE `created_at` IN охват |
| Одобрено | COUNT(`applications`) WHERE `status = 'approved'` AND обработано в охват |
| Отклонено (резерв) | COUNT(`applications`) WHERE `status = 'rejected'` AND обработано в охват |
| Подтверждены (явка) | COUNT(`participations`) WHERE `status = 'attended'` за охват |
| Не пришли без предупреждения | COUNT(`participations`) WHERE `status = 'absent_unexcused'` за охват |
| Конверсия подал → явка | attended / total applications, в % |

> **График «Поэтапная воронка» 🌐** — красивый поэтапный funnel: каждый этап отображается
> сужающейся полосой (Подано → Одобрено → Явка → Неявка без предупреждения). Обезличенный.

---

### Эффективность набора 🌐

Разбивка — **по каждой смене** (`event_days`), не только по мероприятию в целом: одно меро может
идти несколько дней/смен с разной потребностью.

| Показатель | Откуда / как считается |
|------------|------------------------|
| % закрытия слотов по каждой смене | attended по смене / `event_days.volunteer_needed` × 100% — по каждому `event_day` за охват |
| Столбцы таблицы | мероприятие · смена (день) · сколько нужно · сколько пришло · % закрытия |
| Среднее время набора (до закрытия) | 🔒 отдельный блок/график: AVG(дата последнего `approved` → дата меро) по закрытым меро за охват |
| Меро/смены с недокомплектом | `event_days` WHERE (attended / needed) < 0.8 за охват |

> **График «% набора по сменам» 🌐** — столбчатая по сменам.
> Блок **«Среднее время набора» 🔒** вынесен отдельно (см. §Графики).

### Нагрузка персонала 🔒

Обработка заявок — работа не только менеджеров, но и **в первую очередь тим-лидеров** (ТЛ
обрабатывает заявки на своё меро). Поэтому метрики обработки заявок считаются и для ТЛ.

| Показатель | Откуда / как считается |
|------------|------------------------|
| Меро на менеджера (охват) | COUNT(`event_staff`) WHERE `staff_role = 'manager'` GROUP BY `user_id` за охват |
| Заявок обработано менеджером | COUNT(`applications`) WHERE `assigned_by = ?` за охват |
| Ср. время обработки заявки (менеджер) | AVG(`applications.assigned_at - applications.created_at`) GROUP BY `assigned_by` за охват |
| Меро на тим-лидера (охват) | COUNT(`event_staff`) WHERE `staff_role = 'team_lead'` GROUP BY `user_id` за охват |
| Заявок обработано тим-лидером | COUNT(`applications`) WHERE `assigned_by = ТЛ` за охват |
| Ср. время обработки заявки (ТЛ) | AVG(`applications.assigned_at - applications.created_at`) GROUP BY `assigned_by` за охват |

> Полная разбивка тим-лидера (на скольких меро был и т.п.) — в «Статистике тим-лидера» (§2),
> здесь она **не** дублируется: в отчёте за период по ТЛ — только меро как ТЛ и обработка заявок.

### Retention и churn 🔒

| Показатель | Откуда / как считается |
|------------|------------------------|
| % возврата волонтёров | COUNT(волонтёров, у которых есть `participations` и в прошлом периоде, и в текущем) / COUNT всех активных в прошлом периоде × 100% |
| Churn rate | COUNT(волонтёров с `users.churn_score >= const.churn_blacklist_threshold`) / COUNT всех активных, в % |
| Новых попаданий в blacklist | COUNT(`users`) WHERE `status = 'blacklisted'` AND обновлено в охват |

> **Графики блока 🔒:**
> - **Распределение churn** — гистограмма: сколько волонтёров в каждом бакете `churn_score`
>   (0–1, 1–2, … ≥ threshold); порог blacklist отмечается вертикальной линией.
> - **Retention-когорты** — доля вернувшихся из активных прошлого периода.

---

### Проблемные зоны 🔒

| Показатель | Откуда / как считается |
|------------|------------------------|
| Меро с низким рейтингом | `events` WHERE AVG(`event_feedbacks.rating`) < 6 за период — название, рейтинг, количество отзывов |
| Меро с высоким % отказов | `events` WHERE (rejected / total_applications) > 0.5 за период |
| Меро с недобором | attended / needed < 0.8 (дублирует эффективность, но в отдельном блоке с деталями) |
| Волонтёры на грани blacklist | `users` WHERE `churn_score >= (const.churn_blacklist_threshold × 0.8)` — список с текущим скором |

### Сравнение с прошлым периодом 🌐

Доступно только в режиме «по периоду» (в режиме «по мероприятиям» отключено). База сравнения
выбирается **переключателем**, и в шапке блока всегда явно печатается взятый интервал:
`Сравнение с [date_from_prev … date_to_prev] (смежный / год назад)`.

| Вариант базы | Что берётся |
|--------------|-------------|
| **Смежный интервал** (по умолчанию) | Интервал той же длины непосредственно **перед** текущим: неделя → прошлая неделя, месяц → прошлый месяц |
| **Год назад** | Тот же календарный интервал **годом ранее** (эта же неделя/месяц прошлого учебного года — учитывает сезонность волонтёрства) |

| Показатель | Откуда / как считается |
|------------|------------------------|
| Δ часов | Текущий период vs выбранная база, абсолютно и в % |
| Δ мероприятий | Аналогично |
| Δ уникальных волонтёров | Аналогично |
| Δ новых волонтёров | Аналогично |
| Δ конверсии заявок | Аналогично |

### Графики

| График | Доступ | Данные |
|--------|--------|--------|
| Распределение по категориям | 🌐 | Столбчатая: высота = число людей; метрика переключается (волонтёров / часов / мероприятий на категорию) |
| Поэтапная воронка (funnel) | 🌐 | Сужающиеся полосы: Заявки → Одобрено → Явка → Неявка без пред. |
| % набора по сменам | 🌐 | Столбчатая: attended / needed × 100% по каждой смене (`event_days`) за охват |
| Время публикации постов | 🌐 | `events.published_at` по часам суток / дням недели |
| Тайминг заявок (отклик на меро) | 🌐 | См. описание ниже — обезличенный, попадает и во внешний |
| Среднее время набора | 🔒 | AVG(последний `approved` → дата меро) по закрытым меро; распределение по меро |
| Распределение churn | 🔒 | Гистограмма по бакетам `churn_score`, порог blacklist линией |
| Динамика по неделям | 🌐 | Столбчатая: часы (высота) и закрытые смены по неделям охвата |

> **График «Тайминг заявок / отклик на меро».** По оси X — время, отсчёт от «нуля» = самое
> раннее из двух событий по данному меро. На графике **две вертикальные отсечки**:
> - ┊ публикация поста в канале (`events.post_published_at`),
> - ┊ анонс/публикация мероприятия (`events.published_at`).
>
> Точка «0» подписывается тем, что произошло раньше (пост или анонс). Дальше по времени —
> **кумулятивная кривая заявок**: в какой момент и сколько заявок подано
> (`applications.submitted_at − «ноль»`). Внизу — **гистограмма плотности**: за какое время
> после публикации набирается основная масса заявок, бакетами фиксированного шага
> («по-человечески»: 0–1ч / 1–6ч / 6–24ч / 1–3д / >3д). Позволяет увидеть, за какое время
> набирается пик заявок.

## 8. Отчёт простановки часов на Добро.ру 🔒

> Доступен только менеджерам. Операционный отчёт-«воркбенч»: помогает вручную проставить
> волонтёрские часы на сайте Добро.ру. Простановка происходит **вне системы** (на Добро.ру);
> в системе менеджер отмечает факт простановки.
>
> Ключевой принцип удобства: **два разреза** одного и того же набора данных —
> **по человеку** (кому и сколько ставить) и **по ссылке** (что и куда идёт). Менеджер
> выбирает тот, которым ему удобнее закрывать работу.

### Что попадает в отчёт

Строка отчёта = attended-участие (`participations.status='attended'`, `hours > 0`) волонтёра
на меро, у которого `events.dobro_ru_link_kind ∈ {shared, unique}`. Меро с `dobro_ru_link_kind='none'`
**исключаются** (по ним часы на Добро.ру не ведутся). Уже проставленные (`participations.dobro_ru_logged=true`)
по умолчанию скрываются (фильтр «показать проставленные»).

### Фильтры и параметры

| Фильтр | Значения |
|--------|----------|
| Период | неделя / месяц / сезон / произвольный диапазон (по `event_days.day`) |
| Статус простановки | не проставлено (по умолчанию) / проставлено / все |
| Тип ссылки | `shared` / `unique` / оба |
| Конкретная ссылка | выбор `dobro_ru_shared_links` или уникального меро |
| Волонтёр | поиск по ФИО/username |

---

### 8.1 Разрез «По человеку»

Для случая, когда менеджер идёт по волонтёрам и проставляет их часы.

| Поле | Откуда / как считается |
|------|------------------------|
| Волонтёр | `users.first_name / last_name`, `telegram_username` |
| Идентификатор на Добро.ру | `users` (профиль/почта/телефон — что используется для поиска на Добро.ру) |
| Мероприятие | `events.title` |
| Дата | `event_days.day` |
| Часы | `participations.hours` |
| Полная смена | `participations.full_shift` |
| Тип учёта | `events.dobro_ru_link_kind` (`shared` / `unique`) |
| Ссылка для простановки | при `unique` — `events.dobro_ru_link`; при `shared` — `dobro_ru_shared_links.url` (+ `title`) |
| Статус простановки | `participations.dobro_ru_logged` (☑/☐) |
| Действие | отметка `Проставлено` → `dobro_ru_logged=true`, `dobro_ru_logged_at/by` |

**Группировка:** по волонтёру. Под каждым волонтёром — его строки участий; итог «всего часов к простановке».
**Пример:**

```
Иван Петров  (@ivan)  —  к простановке: 3 участия
  ☐ ДОД 2025            12.10   8 ч   [unique]  dobro.ru/event/123   [Проставлено]
  ☐ Конференция «АйТи»  05.10   3 ч   [shared]  «Общая — окт»        [Проставлено]
  ☐ Донор-день          28.09   4 ч   [unique]  dobro.ru/event/456   [Проставлено]
  [ Отметить всё проставленным ]
```

---

### 8.2 Разрез «По ссылке»

Для случая, когда менеджер открывает одну ссылку на Добро.ру и проставляет всех, кто в неё идёт.
Особенно удобно для `shared`-ссылок (много мелких меро в одной ссылке) и для крупных `unique` меро
(один ДОД — сотня волонтёров).

| Поле | Откуда / как считается |
|------|------------------------|
| Ссылка | `dobro_ru_shared_links.title + url` (для shared) или `events.title + dobro_ru_link` (для unique) |
| Тип объекта | `link_type` (`event` / `organization` / `project`) |
| Мероприятия под ссылкой | для shared — все `events` с этим `dobro_ru_shared_link_id`; для unique — одно меро |
| Волонтёры (строки) | все attended-участники этих меро: ФИО, дата, часы, полная смена |
| Всего волонтёров / часов | COUNT(DISTINCT user) и SUM(hours) по ссылке |
| Прогресс простановки | проставлено X из N участий (по `participations.dobro_ru_logged`) |
| Действие | отметка построчно **или** `Отметить всю ссылку проставленной` |

**Группировка:** по ссылке → мероприятия → волонтёры.
**Пример (shared):**

```
🔗 «Общая — конференции, октябрь»   dobro.ru/project/77   [shared]
   Прогресс: 8 / 14 проставлено      Всего: 14 участий · 42 ч
   ├ Конференция «АйТи»  05.10
   │   ☑ Иван Петров     3 ч
   │   ☐ Мария Смирнова  3 ч   [Проставлено]
   ├ Круглый стол        12.10
   │   ☐ …
   [ Отметить всю ссылку проставленной ]
```

**Пример (unique — крупное меро):**

```
🔗 ДОД 2025   dobro.ru/event/123   [unique]
   Прогресс: 60 / 100 проставлено   Всего: 100 участий · 800 ч
   ☐ волонтёр … 8 ч   [Проставлено]
   ☐ волонтёр … 8 ч   [Проставлено]
   [ Отметить всё проставленным ]
```

### 8.3 Сводка по статусу (шапка отчёта)

| Показатель | Откуда / как считается |
|------------|------------------------|
| Участий к простановке | COUNT(`participations` attended, hours>0, kind≠none, `dobro_ru_logged=false`) за период |
| Уже проставлено | COUNT с `dobro_ru_logged=true` за период |
| Меро исключено (`none`) | COUNT(`events` с `dobro_ru_link_kind='none'`) за период — для контроля, что ничего не забыто |
| Незакрытые ссылки | список `shared`/`unique` с прогрессом < 100% |

> Флаг меро `events.dobro_ru_hours_logged` пересчитывается автоматически в true, когда все
> attended-участники меро отмечены (`dobro_ru_logged=true`), и отражается во внутренней карточке меро.
