# Nexus — Design System & Brand Book
### Платформа автоматической обработки заявок, аналитики и мероприятий

Версия 1.0 · Июль 2026

---

## 1. Философия бренда

Nexus — рабочий инструмент, а не витрина. Пользователь заходит в него каждый день: подать заявку, посмотреть статистику, найти мероприятие. Дизайн должен быть **спокойным на длинных сессиях**, **быстрым для сканирования** и **однозначным в статусах** — заявка либо одобрена, либо нет, и это должно считываться за полсекунды.

Три принципа:

1. **Один акцент, весь остальной интерфейс — приглушённый.** Фиолетовый — это единственный по-настоящему насыщенный цвет на экране. Он маркирует действие и активное состояние, а не декор.
2. **Elevation вместо границ.** Карточки отличаются от фона лёгким подъёмом (тень/светлота), а не рамкой. Рамки хрупки в тёмной теме — либо теряются, либо режут глаз.
3. **Mobile — основная платформа.** 80% пользователей открывают Nexus с телефона. Все паттерны проектируются сначала для экрана 375–430px, затем адаптируются на десктоп — не наоборот.

## 2. Цветовая система

Основа — **true grey**, не чёрный и не белый в чистом виде. Акцент — классический насыщенный фиолетовый. Semantic-цвета продублированы отдельно для тёмной темы (не инверсия, а отдельная калибровка).

### 2.1 核心 палитра (Primitives)

| Токен | HEX | Применение |
|---|---|---|
| `--purple-50` | `#F5F1FE` | фон soft-бэйджей (светлая тема) |
| `--purple-200` | `#D9C9FB` | hover-подложки, disabled-акцент |
| `--purple-400` | `#9D6EF0` | акцент в тёмной теме (чуть светлее для контраста) |
| `--purple-500` | `#7C3AED` | **основной бренд-акцент** (кнопки, ссылки, активные иконки) |
| `--purple-600` | `#6B21E0` | hover/active состояние акцента |
| `--purple-700` | `#5B1BC4` | pressed-состояние |
| `--purple-900` | `#2E0F66` | текст на фиолетовом фоне (светлая тема) |

### 2.2 Нейтральная шкала (true grey, лёгкий фиолетовый подтон 2–3%)

| Токен | HEX | Светлая тема | Тёмная тема |
|---|---|---|---|
| `--gray-0` | `#FFFFFF` | фон карточек | — |
| `--gray-25` | `#FAFAFB` | фон страницы | — |
| `--gray-100` | `#F0F0F3` | фон полей ввода, hover строк таблицы | — |
| `--gray-200` | `#E3E3E8` | разделители, границы полей | — |
| `--gray-400` | `#9A9AA5` | вторичный текст | вторичный текст |
| `--gray-600` | `#5C5C68` | — | третичный текст |
| `--gray-800` | `#2B2B33` | основной текст | фон карточек (elevated) |
| `--gray-900` | `#18181D` | — | фон карточек (base surface) |
| `--gray-950` | `#111114` | — | фон страницы (page background) |
| `--gray-1000` | `#FFFFFF` / `#F5F5F7` | — | основной текст |

> Важно: фон тёмной темы — `#111114`, **не** `#000000`. Чистый чёрный убивает ощущение глубины и делает фиолетовый акцент "кричащим". Карточки поднимаются на `#18181D` → `#1F1F26` (hover) без бордеров — только светлота + мягкая тень.

### 2.3 Semantic-цвета (раздельная калибровка для тем)

| Статус | Светлая тема | Тёмная тема | Soft-фон (light) | Soft-фон (dark) |
|---|---|---|---|---|
| Успех / Одобрено | `#16A34A` | `#4ADE80` | `#EAFBF0` | `#132D1D` |
| Ожидание / На рассмотрении | `#D97706` | `#FBBF24` | `#FEF6E7` | `#332508` |
| Отклонено / Ошибка | `#DC2626` | `#F87171` | `#FDECEC` | `#341414` |
| Информация | `#2563EB` | `#60A5FA` | `#EAF1FE` | `#122238` |
| Нейтральный / Черновик | `#6B7280` | `#9CA3AF` | `#F1F1F3` | `#232328` |

Правило: в тёмной теме semantic-цвета **светлее и менее насыщены**, чем в светлой — это даёт читаемость без "неонового" эффекта на тёмном фоне.

### 2.4 Токены как CSS-переменные

```css
:root[data-theme="light"] {
  --bg-page: var(--gray-25);
  --bg-card: var(--gray-0);
  --bg-card-hover: var(--gray-100);
  --border-subtle: var(--gray-200);
  --text-primary: var(--gray-800);
  --text-secondary: var(--gray-400);
  --accent: var(--purple-500);
  --accent-hover: var(--purple-600);
  --accent-soft: var(--purple-50);
  --shadow-card: 0 1px 2px rgba(24,24,29,0.04), 0 4px 12px rgba(24,24,29,0.06);
}

:root[data-theme="dark"] {
  --bg-page: #111114;
  --bg-card: #18181D;
  --bg-card-hover: #1F1F26;
  --border-subtle: rgba(255,255,255,0.06);
  --text-primary: #F5F5F7;
  --text-secondary: #9A9AA5;
  --accent: var(--purple-400);
  --accent-hover: #B388F5;
  --accent-soft: rgba(157,110,240,0.14);
  --shadow-card: 0 1px 2px rgba(0,0,0,0.3), 0 8px 24px rgba(0,0,0,0.35);
}
```

Переключение темы — один атрибут `data-theme` на `<html>`, ни один JS не трогает конкретные цвета в компонентах.

## 3. Типографика

| Роль | Шрифт | Начертания | Применение |
|---|---|---|---|
| UI / Display | **Inter** | 400, 500, 600, 700 | заголовки, кнопки, лейблы, тело интерфейса |
| Числа / данные / коды | **JetBrains Mono** | 400, 500 | ID заявок (`#REQ-2026-0042`), даты в таблицах, суммы, статус-коды |

Inter выбран за нейтральность и отличную читаемость цифр в узких колонках таблиц на маленьких экранах — важно, раз 80% трафика с телефона. Моноширинный шрифт используется точечно: там, где цифры должны выравниваться по колонке (таблицы, ID, даты) — это визуально сигнализирует "это данные", а не текст.

|---|---|---|---|
| `--text-display` | 28px / 34px | 700 | заголовок страницы (десктоп) |
| `--text-display-mobile` | 22px / 28px | 700 | заголовок страницы (мобайл) |
| `--text-h2` | 18px / 24px | 600 | заголовки секций, названия карточек |
| `--text-body` | 15px / 22px | 400 | основной текст, описание мероприятия |

## 4. Сигнатурный элемент: Status Pill

Сквозной визуальный элемент системы — **статус-пилюля**: скруглённый бейдж с точкой-индикатором цвета статуса и текстом. Используется одинаково в заявках, мероприятиях, аналитике — единый язык состояний во всём продукте.

```
● Одобрено      ● На рассмотрении      ● Отклонено      ● Черновик
```

- Точка (6px circle) в основном semantic-цвете.
- Фон пилюли — soft-версия того же цвета.
- Текст — тёмная/светлая версия того же цвета (не серый) — статус должен быть узнаваем даже боковым зрением.

## 5. Layout: сетка и платформы

### 5.1 Десктоп (≥1024px)

```
┌──────────┬────────────────────────────────────────────┐
│          │  Header: поиск · переключатель темы · avatar │
│ Sidebar  ├────────────────────────────────────────────┤
│ 240px    │                                              │
│          │   Контент (max-width 1280px, padding 32px)   │
│ • Дашборд│                                              │
│ • Заявки │   [KPI-карточки в ряд]                       │
│ • Меропр.│   [Таблица / грид карточек]                  │
│ • Аналит.│                                              │
│ • Профиль│                                              │
└──────────┴────────────────────────────────────────────┘
```

Sidebar — borderless, фон чуть темнее контента, активный пункт — вертикальная фиолетовая полоска 3px + soft-фон.

### 5.2 Мобайл (≤480px) — приоритетная платформа

```
┌────────────────────────┐
│  Header (заголовок +   │
│  иконка уведомлений)    │
├────────────────────────┤
│                         │
│  Контент, единая        │
│  колонка, padding 16px  │
│                         │
│  [Карточки в 1 колонку  │
│   или 2 в компактном    │
│   режиме]                │
│                         │
├────────────────────────┤
│ 🏠   📋   ➕   📊   👤  │ ← Bottom Tab Bar
│Дашб. Заявки Новая Стат. Проф.│
└────────────────────────┘
```

Ключевые мобильные правила:
- Нижняя навигация из 5 пунктов, центральная кнопка "+" (создать заявку) — приподнята и залита акцентным цветом (как FAB, но встроена в таб-бар — паттерн маркетплейсов и такси-приложений).
- Все формы создания (мероприятие, заявка) открываются как **bottom sheet**, а не модалка по центру — это стандарт мобильного UX 2026 года: свайп вниз для закрытия, фиксированная кнопка действия внизу.
- Таблицы на мобильном **не сжимаются горизонтально** — превращаются в список карточек, где каждая строка таблицы = карточка с парами "лейбл: значение".

## 6. Компоненты

### 6.1 Таблицы (десктоп) / карточки-строки (мобайл)

Десктоп — классическая таблица, но:
- Без вертикальных разделителей между колонками (только горизонтальные, `--border-subtle`, 1px).
- Строка целиком кликабельна, hover — `--bg-card-hover`, без теней.
- Сортировка — клик по заголовку колонки, стрелка появляется только у активной колонки.
- Числовые колонки (суммы, даты, ID) — моноширинный шрифт, выравнивание по правому краю для чисел.
- Статус — всегда через Status Pill, не через цвет текста.
- Действия (три точки) — справа, меню появляется по клику, не hover (mobile-совместимость логики).

Мобайл — таблица трансформируется в стек карточек: заголовок строки (например, название заявки) + статус-пилюля в правом верхнем углу + 2-3 ключевых поля ниже в виде пар "лейбл / значение".

### 6.2 Создание нового элемента (мероприятие, заявка)

**Десктоп:** модальное окно поверх контента, центрировано, ширина 560–640px, фон затемнён `rgba(17,17,20,0.5)` с лёгким backdrop-blur. Модалка — не на весь экран, шапка с заголовком и крестиком, тело со скроллом при необходимости, футер с кнопками (вторичная слева — "Отмена", основная справа — "Создать").

**Мобайл:** **bottom sheet**, выезжающий снизу на 90% высоты экрана, с "ручкой" (grabber) сверху для свайпа. Кнопка основного действия — прилипшая к низу (sticky footer), всегда видна независимо от скролла формы. Это критично: на телефоне нельзя, чтобы кнопка "Создать" уезжала за пределы экрана при длинной форме.

Структура формы (пример — создание мероприятия):
1. Название (обязательно, лимит символов виден live — `42/60`)
2. Описание — textarea с лимитом **250 символов / ~30 слов**, счётчик символов виден всегда, при приближении к лимиту (>90%) счётчик подсвечивается warning-цветом
3. Диапазон дат — см. 6.3
4. Место проведения
5. Лимит участников (число)
6. Категория (select/chips)

### 6.3 Выбор диапазона дат (Date Range Picker)

- **Десктоп:** два календарных месяца side-by-side, выбор диапазона — клик на старт, клик на конец, промежуточные дни подсвечиваются soft-фоном акцента, начало/конец — заливка акцентом. Сверху — быстрые пресеты ("Сегодня", "Эта неделя", "Этот месяц", "Последние 30 дней").
- **Мобайл:** один календарь на всю ширину, месяцы листаются свайпом или стрелками, пресеты — горизонтальный скролл чипсов над календарём. Поле ввода дат при тапе разворачивается в bottom sheet с календарём внутри (тот же паттерн, что и создание элемента — консистентность).

### 6.4 Карточки мероприятий (маркетплейс-стиль)

Ключевые требования по ТЗ:
- От 0 до 7 актуальных мероприятий на странице.
- Автоматическое ранжирование по дате (ближайшие — первыми), без ручного драг-энд-дропа.
- Дополнительный фильтр (категория / только доступные / поиск).
- Акцент на название + описание (лимит 250 симв / ~30 слов) — значит, описание не обрезается многоточием агрессивно, а получает **2 строки с line-clamp**, этого достаточно для полного короткого описания.
- Разное поведение для десктопа и мобайла.

**Десктоп:** сетка карточек 3–4 в ряд (grid, `minmax(280px, 1fr)`), карточка — обложка (16:9) сверху, затем название (h2, 1 строка, ellipsis), описание (2 строки, line-clamp), нижняя строка — дата + место + Status Pill ("Открыта запись" / "Мест нет" / "Скоро").

**Мобайл (приоритет):** горизонтальные карточки в 1 колонку на всю ширину, обложка слева (квадрат 88×88 или 96×96px) + текстовый блок справа — этот формат в 2 раза компактнее вертикальных карточек и позволяет увидеть 4-5 мероприятий без скролла, что важно при списке 0-7 штук. Название — 1 строка с ellipsis, описание — 2 строки line-clamp, дата и статус-пилюля — в нижней строке текстового блока.

Пустое состояние (0 мероприятий): иллюстрация-заглушка + текст "Актуальных мероприятий пока нет" + (если применимо) кнопка сброса фильтра.

### 6.5 KPI / Аналитика

- Карточки метрик: крупное число (Inter 700, 28-32px) + подпись + дельта (▲/▼ с цветом semantic, никогда просто текст без иконки-стрелки — направление должно считываться и без цвета для доступности).
- Графики — приглушённая, десатурированная палитра линий, отдельная от UI-акцента (акцент бренда резервируется под интерактивные элементы, не тратится на визуализацию данных). Сетка графика — 4-8% светлоты от фона, подписи осей — `--text-secondary`.

### 6.6 Кнопки

| Тип | Светлая тема | Тёмная тема | Применение |
|---|---|---|---|
| Primary | заливка `--purple-500`, текст белый | заливка `--purple-400`, текст `#111114` | основное действие экрана (1 на экран) |
| Secondary | обводка `--border-subtle`, текст `--text-primary` | то же | второстепенное действие |
| Ghost | без фона, текст `--accent` | то же | третичные действия, в таблицах |
| Danger | заливка `--danger` | soft-заливка + текст danger | удаление, отклонение заявки |

Радиус скругления везде — **10px** для кнопок и полей, **14px** для карточек, **999px** (pill) для бейджей и статусов — фирменная деталь, различающая уровни компонентов по степени "финальности" действия.

## 7. Иконография

Единый набор аутлайн-иконок (толщина обводки 1.5px, как в Lucide/Feather) — никаких смешанных стилей (заливка + обводка). Иконки статусов дублируют цвет, но не заменяют текст пилюли — только для доступности.

---

## 8. Доступность

- Контраст текста к фону — не ниже 4.5:1 в обеих темах (проверено для `--text-secondary` на `--bg-card`).
- Статус никогда не передаётся только цветом — всегда текст + цвет + (опционально) иконка.
- Фокус-состояние — всегда видимый outline 2px `--accent`, включая клавиатурную навигацию по таблицам и меню.
- `prefers-reduced-motion` — все transition/анимации отключаются или сокращаются до мгновенных.
