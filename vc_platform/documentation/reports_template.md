# Шаблоны отчётов (PDF · Excel · по мероприятию · простановка часов)

> Документ детально описывает **все выгружаемые отчёты**: макет, состав, порядок
> разделов/колонок, графики и пример каждого файла. Значения внутри примеров записаны как
> `{как считается}` — формула/источник берётся из [reports.md](reports.md) §7–8.
>
> Доступно только менеджерам.

---

## Выбор охвата (общее для всех отчётов за период)

Отчёт строится по одному из **двух взаимоисключающих режимов** охвата:

| Режим | Как задаётся | Что попадает в отчёт |
|-------|--------------|----------------------|
| **По периоду** | Пресет (неделя / месяц / сезон) или ручной диапазон `[date_from … date_to]` через календарь | Все завершённые мероприятия, чьи `event_days.day` попадают в период |
| **По мероприятиям** | Явный выбор набора мероприятий из списка (мультивыбор, по аналогии с выбором диапазона) Мероприятия должны быть отранжированы по дате, визуально быть внутри красивых скугленных блоков, к выбору показывается только последние 15 мероприятий. Для показа остальных сделай выпадающее окно в котором уже идет полный список (у тебя сотни мероприятий и каждый раз видеть все легаси нет смысла). Также там должен быть поиск по названию мероприятия внутри тажке ранжирование по дате| Только выбранные мероприятия; границы дат **игнорируются** |

- Режимы не смешиваются: активен либо диапазон дат, либо набор мероприятий.
- В режиме «по мероприятиям» блок **Сравнение с прошлым периодом** отключается (сравнивать не с чем — период не задан).
- Одна и та же выборка охвата используется всеми форматами (оба PDF, Excel, комплексный).

### Предыдущий период (для блока «Сравнение»)

Только в режиме «по периоду». Менеджер переключателем выбирает базу сравнения:

| Вариант | Что берётся | Когда полезно |
|---------|-------------|---------------|
| **Смежный интервал** (по умолчанию) | Интервал той же длины непосредственно **перед** текущим (неделя → прошлая неделя, месяц → прошлый месяц) | Динамика «неделя к неделе» |
| **Год назад** | Тот же календарный интервал **годом ранее** (эта же неделя/месяц прошлого учебного года) | Учитывает сезонность волонтёрства |

В шапке блока сравнения всегда явно печатается, какой именно интервал взят за базу: `Сравнение с [date_from_prev … date_to_prev] (смежный / год назад)`.

---

## Общие соглашения

- `{…}` в примерах — плейсхолдер: показывает, **как** считается значение, а не конкретное число.
- Источник каждой метрики — соответствующая строка таблиц в [reports.md](reports.md) §7–8.
- Пустые/неопределённые значения выводятся как `—`.
- Отчёты по мероприятиям считаются только по завершённым (`events.event_status='finished'`) — идущие/будущие меро не попадают в статистику задним числом.

# 1. PDF-отчёт за период

PDF выпускается в **двух отдельных вариациях**. Это два самостоятельных готовых документа
(не один файл с пометками):

| Вариация | Кому | Ключевое отличие |
|----------|------|------------------|
| **1A. Внешний PDF** | Руководству, ректорату, грантодателям | Только агрегированные показатели. **Никаких имён конкретных людей** и внутренней кухни (churn, blacklist, нагрузка персонала, комментарии). |
| **1B. Внутренний PDF** | Менеджерам, «держать руку на пульсе» | Всё из внешнего **плюс** персональные и операционные данные (топ волонтёров поимённо, нагрузка персонала, churn, проблемные зоны). |

> **Правило вложенности:** всё, что входит во внешний отчёт, входит и во внутренний.
> Внешний — строгое подмножество внутреннего.

Разметка блоков ниже помечена уровнем доступа:
- 🌐 — **внешний**: попадает и во внешний, и во внутренний PDF;
- 🔒 — **внутренний**: только во внутренний PDF.

# 2. Excel-отчёт за период

Многолистовая книга `.xlsx`. **Полностью дублирует внутренний PDF** (§1B) как агрегаты,
и вдобавок содержит **сырые построчные выгрузки** (заявки, мероприятия) для дальнейшего
анализа. Первая строка каждого листа — заголовок охвата, вторая — шапка колонок.

### Лист «Обзор»

| Показатель | Значение |
|------------|----------|
| Охват | `{период date_from — date_to}` или `{список выбранных меро}` |
| Всего часов | `{SUM(participations.hours) WHERE attended}` |
| Всего мероприятий | `{COUNT(DISTINCT events)}` |
| Уникальных волонтёров | `{COUNT(DISTINCT participations.user_id)}` |
| Закрытых смен | `{COUNT(participations) WHERE attended}` |
| Новых волонтёров | `{COUNT(users) WHERE created_at в охвате}` |
| Людей получили помощь | `{SUM(events.people_helped)}` |

### Лист «Топы»

| Тип | Позиция | Имя / категория | Значение |
|-----|---------|-----------------|----------|
| Волонтёр | `{1..10}` | `{nickname}` | `{SUM(hours) GROUP BY user_id ORDER BY DESC}` |
| Категория | `{n}` | `{event_categories.name}` | `{COUNT(participations) GROUP BY category}` |

### Лист «Распределение по категориям» (данные для графика)

| Категория | Волонтёров | Часов | Мероприятий |
|-----------|-----------|-------|-------------|
| `{event_categories.name}` | `{COUNT DISTINCT user}` | `{SUM hours}` | `{COUNT DISTINCT event}` |

### Лист «Воронка»

| Этап | Значение |
|------|----------|
| Подано заявок | `{COUNT(applications), created_at в охвате}` |
| Одобрено | `{COUNT WHERE status='approved'}` |
| Отклонено (резерв) | `{COUNT WHERE status='rejected'}` |
| Явка | `{COUNT(participations) WHERE attended}` |
| Неявка без предупреждения | `{COUNT WHERE absent_unexcused}` |
| Конверсия подал → явка, % | `{attended / total_applications × 100}` |

### Лист «Эффективность набора (по сменам)»

| Мероприятие | Смена (день) | Нужно волонтёров | Пришло | % закрытия | Ср. время набора |
|-------------|--------------|------------------|--------|------------|-------------------|
| `{events.title}` | `{event_days.day}` | `{event_days.volunteer_needed}` | `{attended по смене}` | `{пришло / нужно × 100}` | `{AVG(последний approved → дата меро)}` |

### Лист «Нагрузка персонала»

| Роль | ФИО | Меро за охват | Заявок обработано | Ср. время обработки |
|------|-----|---------------|-------------------|----------------------|
| Менеджер | `{ФИО}` | `{COUNT event_staff manager}` | `{COUNT applications assigned_by}` | `{AVG(assigned_at − created_at)}` |
| Тим-лидер | `{ФИО}` | `{COUNT event_staff team_lead}` | `{COUNT applications assigned_by=ТЛ}` | `{AVG(assigned_at − created_at)}` |

### Лист «Retention / Churn»

| Показатель | Значение |
|------------|----------|
| % возврата волонтёров | `{вернувшиеся / активные прошлого периода × 100}` |
| Churn rate, % | `{доля users с churn_score ≥ const.churn_blacklist_threshold}` |
| Новых в blacklist | `{COUNT(users) blacklisted за охват}` |

### Лист «Проблемные зоны»

| Категория проблемы | Мероприятие / волонтёр | Метрика |
|--------------------|------------------------|---------|
| Низкий рейтинг | `{events WHERE AVG(rating) < 6}` | `{AVG(rating), кол-во отзывов}` |
| Высокий % отказов | `{events WHERE rejected/total > 0.5}` | `{% отказов}` |
| Недобор | `{events WHERE attended/needed < 0.8}` | `{% набора}` |
| На грани blacklist | `{users WHERE churn ≥ threshold×0.8}` | `{текущий churn_score}` |

### Лист «Сравнение»

Заголовок листа: `База сравнения: {date_from_prev} — {date_to_prev} ({смежный / год назад})`.
(В режиме «по мероприятиям» лист отсутствует.)

| Метрика | Текущий | База | Δ абс. | Δ % |
|---------|---------|------|--------|-----|
| Часы | `{текущее}` | `{база}` | `{тек − база}` | `{(тек−база)/база×100}` |
| Мероприятия | `{…}` | `{…}` | `{…}` | `{…}` |
| Уникальных волонтёров | `{…}` | `{…}` | `{…}` | `{…}` |
| Новых волонтёров | `{…}` | `{…}` | `{…}` | `{…}` |
| Конверсия заявок | `{…}` | `{…}` | `{…}` | `{…}` |

### Лист «Данные для графиков»

| График | Ключ | Значение |
|--------|------|----------|
| Отклик на меро (плотность) | `{бакет времени после публикации: 0–1ч / 1–6ч / 6–24ч / 1–3д / >3д}` | `{COUNT(applications), applications.submitted_at − events.published_at}` |
| Публикация постов | `{час суток / день недели}` | `{COUNT(events.published_at)}` |
| Распределение churn | `{бакет churn_score}` | `{COUNT(users) в бакете}` |
| Динамика по неделям | `{неделя}` | `{SUM(hours), COUNT(participations) по неделе}` |

## 2.1 Лист «Заявки» (сырая построчная выгрузка)

Все заявки за охват — со всей известной информацией. **Одна заявка может занимать несколько
строк**, т.к. при `approved` разворачивается в участия на смены (`event_days`): по строке на
смену. Заявки без участий (new/rejected) — одна строка.

| Колонка | Источник |
|---------|----------|
| ID заявки | `applications.id` |
| Волонтёр (ФИО) | `applications.first_name / last_name` |
| Telegram | `applications.telegram_username` |
| Телефон | `applications.phone` |
| Профиль (user_id) | `applications.user_id` (— если не сматчен) |
| Мероприятие | `events.title` |
| Смена (день) | `event_days.day` — своя строка на каждую смену участия |
| Функция / роль | `applications.functions`, `role_in_event` |
| Когда подал | `applications.submitted_at` |
| Когда загружено в систему | `applications.created_at` |
| Статус заявки | `applications.status` (`new` / `approved` / `rejected`) |
| Кто обработал | `applications.assigned_by` → ФИО |
| Когда обработано | `applications.assigned_at` |
| Пришёл? | `participations.status` (`attended` / `absent_excused` / `absent_unexcused` / —) |
| Полная смена | `participations.full_shift` |
| Часы за смену | `participations.hours` |

## 2.2 Лист «Мероприятия» (сырая построчная выгрузка)

Все мероприятия за охват (или выбранные) — вся имеющаяся по ним агрегированная информация.

| Колонка | Источник |
|---------|----------|
| ID | `events.id` |
| Название | `events.title` |
| Организация | `organizations.name` |
| Организатор | `organizers.first_name / last_name` |
| Категории | `event_categories.name` (через map, через запятую) |
| Даты (первая–последняя) | MIN/MAX `event_days.day` |
| Кол-во смен | `COUNT(event_days)` |
| Локация(и) | `locations.name` |
| Статус меро | `events.event_status` |
| Статус набора | `events.recruit_status` |
| Нужно волонтёров (итого) | `SUM(event_days.volunteer_needed)` |
| Подано заявок | `COUNT(applications)` |
| Одобрено | `COUNT(applications approved)` |
| Явка | `COUNT(participations attended)` |
| % закрытия | `явка / нужно × 100` |
| Всего часов | `SUM(participations.hours) attended` |
| Людей получили помощь | `events.people_helped` |
| Средний рейтинг | `AVG(event_feedbacks.rating)`, кол-во отзывов |
| Менеджер(ы) | `event_staff manager` → ФИО |
| Тим-лидер(ы) | `event_staff team_lead` → ФИО |
| Тип учёта Добро.ру | `events.dobro_ru_link_kind` |
| Часы на Добро.ру проставлены | `events.dobro_ru_hours_logged` |

Объединённая выгрузка за один охват одним пакетом:

# 5. Отчёт простановки часов на Добро.ру

> Операционный «воркбенч» для менеджеров: помогает вручную проставить волонтёрские часы на
> Добро.ру. Простановка происходит **вне системы**; в системе менеджер отмечает факт.
> Формат — **Excel** (удобно выделять/фильтровать/копировать), при необходимости и PDF.
>
> Полное описание логики, фильтров и двух разрезов — в [reports.md](reports.md) §8.
> Здесь — макет выгрузки.

### Что и зачем

Менеджеру нужно удобно увидеть: **на какую ссылку**, **кому** и **сколько часов** проставить.
Ключевой принцип — **два разреза** одного набора данных. Менеджер выделяет блок и аккуратно
проставляет всё разом.

В отчёт попадают attended-участия (`hours > 0`) на меро с `dobro_ru_link_kind ∈ {shared, unique}`.
Меро с `none` исключаются. По умолчанию скрыты уже проставленные (`dobro_ru_logged=true`).

### 5.1 Разрез «По ссылке» (основной)

Менеджер открывает одну ссылку Добро.ру и проставляет всех, кто в неё идёт. Ссылка — главный
объект работы, поэтому она в заголовке блока; участники — таблицей под ней.

```
🔗 «Общая — конференции, октябрь»   dobro.ru/project/77   [shared]
   Прогресс: 8 / 14 проставлено      Всего: 14 участий · 42 ч
   ┌──────────────┬───────────────────┬───────┬────────────┐
   │ Волонтёр     │ Мероприятие · день│ Часы  │ Проставлено│
   ├──────────────┼───────────────────┼───────┼────────────┤
   │ {ФИО}        │ {events.title ·   │{part. │  ☐ / ☑     │
   │              │  event_days.day}  │hours} │            │
   └──────────────┴───────────────────┴───────┴────────────┘
   [ Отметить всю ссылку проставленной ]

🔗 ДОД 2025   dobro.ru/event/123   [unique]
   Прогресс: 60 / 100 проставлено   Всего: 100 участий · 800 ч
   … (таблица волонтёров этого меро)
```

### 5.2 Разрез «По человеку»

Менеджер идёт по волонтёрам. Здесь ссылки важнее ФИО, поэтому имя — подпись блока, а работа
идёт по строкам-ссылкам под ним.

```
Иван Петров  (@ivan)  —  к простановке: 3 участия, 15 ч
   ┌───────────────────────┬─────────────────┬───────┬────────────┐
   │ Ссылка (куда ставить) │ Мероприятие·день│ Часы  │ Проставлено│
   ├───────────────────────┼─────────────────┼───────┼────────────┤
   │ dobro.ru/event/123    │ ДОД 2025 · 12.10│  8    │   ☐ / ☑    │
   │ «Общая — окт» [shared]│ Конф.АйТи ·05.10│  3    │   ☐ / ☑    │
   └───────────────────────┴─────────────────┴───────┴────────────┘
   [ Отметить всё проставленным ]
```

### 5.3 Сводка (шапка)

| Показатель | Источник |
|------------|----------|
| Участий к простановке | `COUNT(participations attended, hours>0, kind≠none, logged=false)` |
| Уже проставлено | `COUNT logged=true` |
| Меро исключено (`none`) | `COUNT(events dobro_ru_link_kind='none')` — контроль |
| Незакрытые ссылки | список `shared`/`unique` с прогрессом < 100% |

> Excel-выгрузка простановки строится в обоих разрезах на отдельных листах («По ссылке»,
> «По человеку») + лист «Сводка». Флаг `events.dobro_ru_hours_logged` пересчитывается в true,
> когда все attended-участники меро отмечены.
